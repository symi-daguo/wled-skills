# 收尾检查清单（说"做完了"之前逐条过）

> 这张表是为了防止"看起来做完了、其实留了坑"。任何一项打不了勾，就不要说完成。
> 依据：本项目实测踩过的坑 + 社区同类技能的 done-checklist 做法。

## 必须打勾（缺一条就是没做完）

- [ ] **灯亮着且是客户要的样子** —— 用 `verify_live.py` 回读真实帧缓冲，
      不是只看 `/json/state`。字段会说谎：`lor>0` 时 `lm` 仍报 `UDP` 但所有推流帧都被丢弃。
- [ ] **每一颗都亮** —— `leds_never_lit == []`，段的 `start..stop` 无缝覆盖 `0..N`。
- [ ] **颜色没被吃** —— `col` 的槽数与设备能力一致（RGB 3 元 / RGBW+ 4 元），
      且 4 元时 `cct` 已给。RGBW 灯带上 `col[0]` 的 R 偏小是拆白的正常结果，不是 bug。
- [ ] **目标是这台灯带** —— 配方灯数 == `info.leds.count`；双灯带场景下每次都带了 `--ip`。
- [ ] **写前备份过** —— `wled.py backup` 或 `apply_recipe.py --backup`，
      `backups/` 里能看到 presets + cfg。
- [ ] **收尾干净** —— `wled.py restore`（熄灯 + 归还 `if.sync.recv`）；
      设备上不留测试预设（`pdel` 删掉），段恢复成 `fx=0` + 黑。
- [ ] **没留内网 IP 在仓库里** —— `config.json` / `.wled_cache.json` / `backups/` 均已 gitignore；
      文档里只用「70 颗那条 / 490 颗那条」指代。

## 交付给客户时额外确认

- [ ] **一键触发可用** —— `wled.py save "<名字>"` 已存成设备端预设，并回读确认
      `presets.json` 里名字是中文原文（不是 `\u6f14...` 这种转义）。
- [ ] **名字能 recall** —— `wled.py recall "<名字>"` 能命中（先查 `recipes/`，再查设备预设）。
- [ ] **客户能自己触发** —— 告诉他在 WLED App 里点哪个预设号；有米家场景的话一并说明。

## 反模式（看到就别交付）

| 现象 | 真实原因 |
|---|---|
| "参数都对，但灯不对" | 只看了 `/json/state`，没回读帧缓冲 |
| "只有一小段亮" | 旧段没清（`clear_stale_segments`），新段被上层遮住 |
| "灯是黑的但命令成功" | `on=false` 或 `lor>0`；推流点不亮，或像素被丢弃 |
| "颜色发灰、不够亮" | RGBW 灯带没拆白，白通道全程 0 |
| "同步忽然失效" | `apply_recipe` 关掉了 `if.sync.recv` 而没 `--release` |
| "灯带自己亮了/变了色" | 局域网他机 UDP 同步；或设备端预设被别的客户端触发 |
