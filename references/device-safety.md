# 设备安全规则（写操作前必读）

> 这一章不是可选项。WLED **没有账号体系**：同一局域网里任何人几乎都能调用它的全部接口，
> 设置 PIN 和 OTA 锁只保护其中一部分。下面的规则把 Agent 的动作限制在"用户真正要求的那一件事"上。
>
> 依据：WLED 16 实测 + 官方文档；并与社区同类技能的写保护策略做了对齐（见文末差异说明）。

---

## 一、哪些读取是免费的，哪些 GET 其实在写

| 类别 | 接口 | 说明 |
|---|---|---|
| 免费读 | `GET /json/*`、`/presets.json`、`/cfg.json`、除 `/settings/lock` 外的设置页 | 随便读 |
| 有条件读 | `ws://<ip>/ws` + `{"lv":true}` | **必须先看 `GET /json/info` 的 `ws` 客户端数**，同时只服务一个客户端 |
| 有条件读 | 串口单字节 `v` | 仅在 DTR/RTS 都拉低的串口上免费 |
| 会触发动作 | `GET /json/net` | **会启动一次 Wi-Fi 扫描**，只有用户要网络列表时才调 |
| **其实是写** | `/reset`（重启）、`/settings/lock`（对所有客户端锁设置）、`/update?revert`（回滚固件）、`/win&...`（执行 HTTP API） | 全部按写操作对待；裸 `GET /win` 只读 |

## 二、写之前：备份 + 说清楚 + 一次授权一次变更

1. **先备份**，两个文件都要：`/presets.json` 与 `/cfg.json`。

   ```bash
   python3 scripts/apply_recipe.py --backup            # 落到 backups/<ip>-<时间戳>.json
   python3 scripts/apply_recipe.py --backup --ip <ip>  # 多灯带必须指定目标
   ```

2. **再说清楚三件事**：会改什么、最坏结果、怎么回退。
3. **等一个"是"。一次授权只覆盖一次变更**，不要拿一次同意去连做多步。
4. 设备 HTTP 不通时，**明确说"无法通过 HTTP 备份"**，不要假装备份过；需要 `esptool read-flash` 走 USB 时，同样先拿到同意。

## 三、这几件事只能由用户点名要求

固件/引导程序更新、`erase-flash`、改 PIN、恢复出厂（`POST /settings/sec` 的 `RS` 字段）、
任何 Wi-Fi 或 AP 变更。**Agent 不得自行发起**，即使用户在抱怨"灯连不上"。

## 四、绝不 POST 残缺的 `/settings/*` 表单

设置页表单是**全量提交**：没写的字段会被存成空值或关闭状态，一次误提交能把设备配置清掉。
改配置的正确做法：

```bash
GET  /json/cfg                       # 先读
POST /json/cfg  {要改的键 + 从上面原样复制的 5 个必带键}
GET  /json/cfg                       # 再读，逐键比对
```

改完必须回读比对，不能只看 HTTP 200。

## 五、PIN 与 OTA 密码

- **问用户要**，不要猜、不要遍历、不要打印、不要写进日志或配方文件。
- 只在**当次调用**使用：走 stdin，或放在用户私有文件里、用完立即删除。
- **PIN 输错一次，会对所有客户端锁住设置页** —— 所以更不能重试。
- 判断有没有 PIN：看 `GET /settings/sec` 的**状态码**，**不要用 POST 去试**。

## 六、非幂等调用，失败也不要重试

下面这些一重试就是两次动作：

| 调用 | 为什么不能重试 |
|---|---|
| `{"on":"t"}` | 是**切换**，重试等于又切回去 |
| `{"np":true}` | 下一预设，重试跳两步 |
| `{"psave":N}` | 覆盖保存，重试可能覆盖掉中间状态 |

正确做法：**先读状态，再发"目标值"**（`{"on":true}` / `{"ps":N}`），而不是发相对动作。

## 七、永远不要把设备暴露到公网

WLED 是**纯 HTTP、无登录、允许任意 Web 源**。任何端口转发、内网穿透、公网反代都是高危配置，
不要建议、不要代做。

## 八、本项目的额外约定（比通用规则更严）

| 约定 | 原因 |
|---|---|
| 双灯带场景**每次都要 `--ip`** | 发现器只返回一台，不指定就会写到另一条灯带上 |
| **测完必须熄灯 + `--release`** | `apply_recipe.py` 会关闭设备的 `if.sync.recv`；不还原会让客户的主从同步静默失效 |
| `config.json` / `.wled_cache.json` / `backups/` **不入库** | 含内网 IP；对外材料不出现内网地址 |
| 改完必须**回读像素**（WebSocket Peek） | 字段级判定会骗人：`lor>0` 时 `lm` 仍报 `UDP`，`col` 变了灯却没变 |

## 与社区同类技能的差异

| 主题 | 本技能 | 说明 |
|---|---|---|
| 写前备份 | `--backup` 落 `backups/`，含 presets + cfg | 与社区"写前备份两个文件"一致 |
| 一次授权一次变更 | 同 | 采纳 |
| 危险 GET | 同（`/reset`、`/settings/lock`、`/update?revert`、`/win&`） | 采纳 |
| 残缺设置表单 | 同（禁止 POST 部分 `/settings/*`） | 采纳 |
| 非幂等不重试 | 同 | 采纳 |
| **效果生成** | **有**：14 组场景配色 + 图片/视频取色 + 动态配方 + 能力自适应出码 | 社区同类多为薄 HTTP 封装，无效果生成 |
| **像素级验收** | **有**：WebSocket Peek 回读真实帧缓冲 | 社区同类只读 `/json/state` 字段 |
| **设备能力自适应** | **有**：按 `info.leds.lc` 出 3/4 通道码 | 社区同类写死 RGB |
