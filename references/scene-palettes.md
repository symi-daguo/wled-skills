# 场景配色表（场景名 → 三色渐变）

> **这不是"1 分钟动态配方"的替代品。** 这里给的是**静态氛围色**：
> 一条灯带铺一段 A→中间色→B 的渐变，不下发播放列表、不做时间演变。
> 需要"会动的 1 分钟光效"时走 `references/effect-templates.md`。
>
> 用法：`python3 scripts/scene_palette.py --list` 看全部场景；
> `python3 scripts/scene_palette.py "热带海岸"` 出配方 JSON；
> 加 `--apply` 直接下发到局域网 WLED。

---

## 一、为什么是三色、为什么顺序是反的

| 事实 | 源码依据 |
|---|---|
| `pal 4` = **Color Gradient**，构成是 `(ter, sec, prim)` | `wled00/FX_fcn.cpp:257-262` `targetPalette = CRGBPalette16(ter,sec,prim)` |
| ⇒ 渐变顺序是 **`col[2]` → `col[1]` → `col[0]`** | 即起点色放 `col[2]`、终点色放 `col[0]`，写反会得到反向渐变 |
| `pal 5` = 主/次/三 **三段分明**，不做混合 | 同文件 `:263-271`（各重复 5 次） |
| `pal` 必须显式给 2/3/4/5，**不能用 0** | `pal:0` 时 `color_from_palette()` 直接返回段色，效果可能把颜色换掉 |
| 段色是**定长 3 槽**，少给一槽会让渐变断掉 | 段色数组 `NUM_COLORS = 3` |

所以一段 A→B 的渐变必须补一个**中间色**，并按下表落位：

```
col[2] = A（起点）    col[1] = 中间色    col[0] = B（终点）
pal    = 4
```

## 二、为什么用 Shimmer(fx 161) 且 `sx=0`

| 方案 | 结果 |
|---|---|
| `fx 46 Gradient` + `sx=0` | **仍会动**：`counter = strip.now * ((0>>2)+1)` = `now`，相位继续走，实测静止帧占比 36% ⇒ 「一抖一抖」 |
| **`fx 161 Shimmer` + `sx=0`** | **真静止**：`wled00/FX.cpp` 的 `else { position = (SEGLEN << 7); }`，位置锁死在段中心，不移动 |
| Shimmer 的取色 | `color = SEGMENT.color_from_palette(i * 255 / SEGLEN, false, false, 0)` ⇒ **整条铺满 0..255 全段调色板**，才是真正的 A→中间→B |

带宽 `c1` 必须**拉满到 255**：`radius = (c1 * SEGLEN >> 7) + 1` ≈ `2 × SEGLEN`，
这样整条都在带内（`dist < radius<<8`），且端点最多只向 `col[1]` 混 25%（`blend = dist/radius`），
不会出现「半条变成纯中间色」。

**中间色不写死，由脚本在线性光空间取中点。**
为什么不走 HSV 插值：色相"最短路径"会跑出歧义结果——蓝 `#00B4D8` → 金 `#FFD166`
的色相最短路径经过绿色，会得到一块**荧光绿**，完全不是"海边日落"；
线性光平均得到的 `#BAC3AB`（雾感灰绿）才是物理上正确的地平线过渡。
需要精确控制时用 `--mid '#RRGGBB'` 覆盖。

## 四、生成的两档档位

| `--profile` | `sx` | 观感 | 用途 |
|---|---|---|---|
| `still`（默认） | `0` | 完全静止的渐变 | 氛围色、背景墙、待机 |
| `breath` | `40` | 极慢的呼吸推移（实测仍在走，只是很慢） | 需要"活着"的感觉时 |

> `breath` 档会重新引入 Shimmer 的相位移动。要**完全静止**就用 `still`。

## 五、与技能既有规则的关系

- **R1 全覆盖**：单段 `0..N` 铺满，`verify_live.py` 的 `leds_never_lit == []` 仍要过。
- **R2 不黑**：本表 14 组无黑色；`still` 档整条恒亮。
- **R5 颜色最佳**：`seg_bri = 255`、全局 `bri` 由 `--bri` 给（默认 200）。
- **R7 丝滑**：`still` 档没有运动，不适用；`breath` 档走 Shimmer 子像素路径，实测静止帧占比 0%。

## 六、现场执行口径（两条灯带，别搞错）

| 灯带 | 灯珠 | 用法 |
|---|---|---|
| 70 颗（`wled-772980`） | 70 | 默认，`--leds` 可省略；`references/` 里所有模板都按这个灯数写 |
| 490 颗 | 490 | **必须** `--leds 490`；70 颗的模板不要往它身上套 |

下发前先 `python3 scripts/discover_wled.py` 确认目标 IP，再把配方的灯珠数和
`/json/info` 的 `info.leds.count` 对一遍——对不上就是选错灯带了。

**测完两步收尾，缺一步都算没做完：**

```bash
curl -s -X POST "http://<ip>/json/state" -H "Content-Type: application/json" -d '{"on":false}'
python3 scripts/apply_recipe.py --release
```

第一步熄灯（若设备处于实时模式，还要补 `{"live":false}`，否则最后一帧会锁住）；
第二步还原被 `apply_recipe.py` 关掉的 `if.sync.recv`（bri/col/fx/pal），
不改回来会让客户的局域网主从同步静默失效。

> 内网 IP 一律不进仓库：`config.json` 与 `scripts/.wled_cache.json` 都已 gitignore，
> 文档里只用「70 颗那条 / 490 颗那条」指代。

## 七、实机验收记录（70 颗那条）

| 场景 | 触发方式 | 首颗 → 末颗（真实帧缓冲） | 静止 | 全黑 | 相邻色差 |
|---|---|---|---|---|---|
| 热带海岸 | `"热带海岸"` 精确名 | (47,184,205) → (235,205,120) | 是 | 0 颗 | 均值 4.3 / 最差 9 |
| 春日樱花 | `"春天樱花那种粉"`（别名 + 反向子串） | (255,192,202) → (255,237,225) | 是 | 0 颗 | 均值 1.1 / 最差 3 |

两组的首颗色都等于 `col[2]`（起点色）向 `col[1]` 混 25%，末颗等于 `col[0]`（终点色）同样混 25%，
与「`pal 4 = (ter, sec, prim)`」的推导一致——这是槽位顺序没错的直接证据。
